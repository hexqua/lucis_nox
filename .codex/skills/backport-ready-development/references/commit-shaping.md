# コミット構成

## 基本原則

- 1機能または1修正を、非mergeコミットの連続した系列として追跡できる状態にする。
- 共通ロジック、NeoForge固有接着コード、generated/resource、ドキュメントを分離できるか実装前に検討する。
- 無関係な整形、rename、広域整理を機能コミットへ混ぜない。
- 分離によって中間コミットがビルド不能になる場合は、機械的な分割より成立する変更単位を優先する。

## 推奨する並び

1. 共通ロジックと動作テスト
2. 1.21.1 / NeoForge固有の登録・接着コード
3. datagenとgenerated/resource
4. 関連ドキュメント

すべてを必ず別コミットにする規則ではない。実際のbackportでどの非mergeコミットを選び、何をtarget側で補正するか説明できることを優先する。

## レビュー結果

- `完全backport候補`、`target側再実装を伴う候補`、`対象外`のいずれかを示す。
- 候補となるコミットと、1.20.1へ持ち込まないNeoForge固有部分を示す。
- 追加の分割が必要な場合は、実装を変える理由と期待するコミット境界を示す。
- 実際のcherry-pickは開始しない。
