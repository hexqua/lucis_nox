# クライアント確認の引き継ぎ

今回の変更で人間が確認すべきクライアント挙動を、実行可能なシナリオとして最終報告へ引き継ぐ。自動検証の境界と例外条件はリポジトリの `AGENTS.md` に従う。

## シナリオの整理

- 変更内容と実施済みの検証から、client で確認する対象と理由を特定する。作業中に自動検証で確認しようとしていたケースも含める。
- 今回の変更に必要なケースだけを選び、無関係な変更に定型確認を追加しない。すべての `runClient...` 構成を網羅する必要はない。
- 通常操作に加え、変更に関係する境界条件や回帰確認が必要なら含める。
- 起動構成、必要な optional MOD、設定、ゲームモード、アイテム等の前提を示す。存在する構成や確認できた仕様に基づき、前提や期待結果が不明なら推測で埋めず未確定として示す。

## 確認状態

- Codex が実施していないことと、人間が実施していないことを区別する。人間の結果が伝わっていなければ「人間確認結果は未把握」とする。
- 「未実施」は未実施と分かっている場合に使用する。「一部確認済み」は確認できた範囲と残りを区別する。
- 「人間確認済み」は、ユーザーから確認できたと伝えられた場合など、既に得られた情報に基づいて記載する。根拠は「ユーザーから当該操作の確認済みとの連絡あり」程度に簡潔に示し、伝えられた範囲を超えて成功を推測しない。
- 例外的な自動検証で確認できた範囲は、その方法とともに区別して示す。起動成功やログ確認だけで表示・操作のケース全体を成功扱いにしない。
- 根拠はエージェントが出力内容を裏付けるための情報であり、人間に所定の報告、証跡提出、ステータス更新を要求するフローではない。結果が未把握でも報告を催促せず、確認済みと推測しない。

## 出力

最終報告に、ケースごとに次の内容をまとめる。短いケースは箇条書き、複数ケースは表など、確認者が実行しやすい形式にする。

- 確認対象と理由
- 起動構成と前提条件
- 再現可能な操作手順
- 具体的な期待結果
- 確認状態と、確認済みの場合は既に得られた根拠

## 作業境界

- この Skill は報告だけを行い、client 起動、GUI 自動操作、実装修正、テスト追加、個別の記録ファイル作成、コミットを行わない。
- 必要な自動検証とローカルレビューを終えていれば、シナリオを出力して人間へ引き渡す。人間確認が未実施または結果未把握であることだけを理由に作業を継続しない。
- この報告は人間の確認やコミット許可を代替しない。コミットの実行可否は適用される指示に従う。
